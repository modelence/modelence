This page is written for a coding agent. It describes what a local environment is and the steps to
connect a project to one. If you are a person, hand it to your agent:

```text
Use https://docs.modelence.com/setup.md to connect this project to a Modelence local environment
```

## What a local environment is

- **The app runs on the user's machine**, started from the project directory. Modelence does not
  build or host it; to put the app online, deploy it to a cloud environment as described in
  [Deploy Setup](/deploy/setup).
- **The environment holds what the app uses**: the connection strings of its resources (databases,
  caches) and its settings. They reach the app when it starts, so they never need to be copied into
  the project.
- **The dashboard shows the running app** on the environment's **Overview**, so the user can see
  whether it is up.

## Connecting a project

Follow these steps in order.

1. **Check whether the project is already connected.** A `.modelence.env` file at the project root
   means it is. Ask the user whether to connect it to a different environment before going on; if
   they want to, the command in the next step asks to overwrite the file, so run it as
   `echo y | npx modelence@latest setup`.

2. **Run `npx modelence@latest setup`** in the project root yourself, with a timeout of at least
   10 minutes. It opens the browser, where the user signs in and picks the organization, application
   and environment, or creates a new application or environment there. Tell the user to confirm
   there, then wait for the command to finish. Pass `--new` when the user wants a new environment
   rather than an existing one.

3. **Check the files it wrote.**
   - `.modelence.env` holds the project's connection to the environment, including a secret token.
     It must never be committed: add it to `.gitignore` if it is not there yet.
   - `.modelence/project.json` records which application the project belongs to. Commit it, so the
     next setup or deploy from any copy of the repository preselects that application.

4. **Start the app with `npx modelence@latest dev`** in the project root, in place of the project's
   own development command. It starts the project with the environment's values and reports it to
   the environment. It keeps running; leave it running in the background.

5. **Confirm it is connected.** Tell the user to open the environment in the Modelence dashboard: its
   **Overview** shows the app as running instead of waiting for it.

<Note>
Apps built on the Modelence framework (with the `modelence` dependency) need no
`modelence.config.json`, and one must not be added to them: `modelence dev` recognizes the
dependency and starts them as it always has.
</Note>
