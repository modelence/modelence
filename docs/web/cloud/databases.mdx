Modelence Cloud runs managed MongoDB, PostgreSQL and Redis databases next to the app. Each one is
created in the environment's [region](/cloud/regions), its connection string reaches the app as an
[environment variable](/cloud/environment-variables), and it is [backed up](/cloud/backups) in
production.

A database is a resource in
[`modelence.config.json`](/deploy/config), and `env` passes its
connection string to the app:

```json modelence.config.json
{
  "resources": {
    "api": {
      "type": "service",
      "build": { "commands": ["npm ci"] },
      "start": { "commands": ["node server.js"] }
    },
    "main-db": { "type": "postgres" },
    "cache": { "type": "redis" }
  },
  "env": {
    "DATABASE_URL": { "type": "resource", "resource": "main-db", "output": "url" },
    "REDIS_URL": { "type": "resource", "resource": "cache", "output": "url" }
  }
}
```

A `url` output is the full connection string, over TLS. The other outputs are its parts, for
clients that read them separately. The [reference](/deploy/config)
lists every output.

## Sizes

`modelence deploy` asks for the size of a new PostgreSQL database or Redis cache in the browser, on
the deploy that creates it. A deploy from CI fails with a link instead: pick the size there, then
deploy again. The picker shows the monthly price of each size.

The free PostgreSQL size is available on every plan, Free included, up to 3 per organization. It
sleeps after 5 minutes without queries, and the next query wakes it in under a second, so it suits
staging and small apps. The other sizes never sleep and need a paid plan.

## Lifecycle

A deploy creates every managed resource the file declares that the environment doesn't have yet, and
the new version starts only once they are ready. Resources are matched by name, so the same file
works in every environment:

- A resource that already exists is kept as it is, with its data and its size.
- A resource removed from the file is not deleted, and it is billed until it is.
- Renaming a resource creates a new, empty one, and the old one stays until it is deleted.

Deleting a managed resource permanently deletes its data and its backups.

## Databases hosted elsewhere

An app can also use a database hosted somewhere else, such as Supabase, Neon or PlanetScale. Keep its
connection code and declare its URL and keys in `env` as secrets.
